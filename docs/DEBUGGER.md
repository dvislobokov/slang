# Отладчик

Цель: отладка уровня Delve/dlv и VS Code-интеграции, но быстрее там, где
Delve интерпретирует: условные точки останова, вычисление выражений,
перечисление задач. Преимущество Slang — компилятор на LLVM (DWARF
бесплатно) и компилятор как библиотека (отладчик компилирует условия и
выражения в нативный код).

## Этап 1: DWARF + lldb/gdb + DAP

- Кодогенерация пишет DWARF 5 через LLVM `DIBuilder`: compile unit на файл,
  функции (включая мономорфизированные generics с читаемыми именами
  `Max<int>`), параметры и локальные переменные с местоположениями, строки,
  инлайн; типы: примитивы, структуры с полями, указатели, `weak`, срезы,
  строки, map, кортежи, enum (простые и с данными как tagged union),
  интерфейсы (fat pointer), `T!` (как union {value, error}), `Task<T>`,
  замыкания, фреймы корутин (локальные переменные видны после `await`).
- Включено по умолчанию в debug-сборке; `slang build --release -g` для
  release с отладочной информацией; `--strip` убирает.
- **Форматтеры типов**: `tools/lldb/slang_formatters.py` (string → текст,
  slice → массив, map → пары, `T!` → значение или `error: ...`, enum →
  имя варианта с полями, interface → динамический тип и значение, Task →
  состояние) и `tools/gdb/slang_printers.py`. Подключаются автоматически
  через `slang debug --lldb` или вручную.
- **DAP**: `lldb-dap` с форматтерами; клиент в `editors/vscode`
  (конфигурация `type: "slang"`, запуск `slang build` перед отладкой,
  `program`/`args`/`env`/`cwd`, attach по pid). Работают точки останова,
  условия (вычисляются lldb — медленно, см. этап 2), шаги, стек,
  переменные, watch, REPL-выражения в синтаксисе lldb.
- Паника останавливает отладчик в месте паники (точка на `slang_panic`).

## Этап 2: `slang debug` — собственный отладчик

Отдельный бинарник на Rust: ptrace (Linux), Mach (macOS), Win32 Debug API
(Windows); DWARF через `gimli`; протокол DAP для редакторов и CLI в духе
dlv/gdb (`b`, `c`, `n`, `s`, `p`, `bt`, `tasks`, `task N`, `goto`).

### Чем быстрее Delve

| Delve | `slang debug` |
|---|---|
| Условная точка: остановка процесса на каждом попадании, условие вычисляет отладчик | Условие компилируется нашим компилятором в нативную функцию и внедряется в процесс; остановка только когда условие истинно (в сотни раз меньше переключений на горячих точках) |
| Выражения: собственный интерпретатор подмножества Go, медленный и неполный | Выражение компилируется против DWARF-типов и выполняется в процессе; вызовы функций, методы, `?`, generics — полный язык |
| Логпоинты через остановку | Логпоинт — внедрённый код, пишущий в канал отладчика без остановки |
| Горутины: чтение всех структур рантайма при каждом запросе, секунды на больших программах | Планировщик ведёт компактный список задач для отладчика (состояние, точка `await`, родитель); перечисление за миллисекунды |
| Шаг через канал/`select` уводит в планировщик | `next` понимает `await`: продолжение в той же задаче после возобновления; `step into` в async-функцию |
| Оптимизированный код отлаживается плохо | DWARF из LLVM с инлайном и локациями; «optimized out» только где это правда |

### Дополнительно

- Память: счётчик ссылок объекта, кто удерживает (по таблицам
  `--leak-check`), циклы прямо в сессии, остановка на `Drop`.
- Точки на ошибках: `break on error NotFound` — остановка, когда создаётся
  ошибка данного типа или проходит через `?` в указанной функции.
- Запись и воспроизведение: интеграция с `rr` (обратное исполнение),
  позже свой механизм.
- Горячая замена функций в dev-сборке (общий механизм с hot reload GUI).
- Core-dumps: `slang debug core app.core` с теми же форматтерами.
- Remote: `slang debug --listen :2345` и подключение из редактора (как
  `dlv --headless`), в контейнерах и на серверах.
- `slang debug test` — отладка одного теста.

### Архитектура

```
editors (VS Code, IDEA)  ──DAP──▶  slang-debug (Rust)
                                   ├─ dwarf (gimli): типы, локации, строки
                                   ├─ target: ptrace / mach / win32
                                   ├─ expr: компилятор Slang как библиотека →
                                   │        LLVM → объектный код → инъекция
                                   ├─ tasks: чтение списка задач рантайма
                                   └─ cli
```

Рантайм помогает отладчику: структура `slang_debug_info` с указателями на
список задач, таблицы типов и текущие worker-потоки, стабильная между
версиями (ABI.md §19).

## Этапы

1. DWARF в кодогенерации (все типы, локальные переменные, корутины),
   форматтеры lldb/gdb, `lldb-dap` в VS Code, тесты: скрипты lldb,
   проверяющие значения на точках останова в examples/.
2. `slang-debug`: ptrace + gimli, точки останова, шаги, стек, переменные,
   DAP; замена `lldb-dap` в VS Code.
3. Компилируемые условия и выражения, логпоинты, список задач и
   `await`-aware шаги.
4. macOS и Windows бэкенды, remote, core-dumps.
5. Память и ошибки как объекты отладки, `rr`, горячая замена.
